Numeraire SwissKnife combines account ownership with scoped administrative permissions.

- `/v1/me` routes are scoped to the authenticated account and, where applicable, an owned wallet ID in the path. They do not require administrative permission scopes.
- Non-`/me` routes check the permission required for the operation.

## Permissions

Permissions are a list of strings such as `read:account`, `write:account`, `read:wallet`, and `write:transaction`.

- For OAuth2/OIDC, the external identity provider adds the effective permissions to the token. Token claims are authoritative and cannot be replaced through the account API.
- For local JWT, permissions are stored on the account. The initial account receives all permissions, and an admin can replace another local account's grants through `PUT /v1/accounts/{id}/permissions`.
- API keys always retain the account-scoped `/v1/me` baseline. Their stored permission subset adds administrative routes and can be revoked independently.

### Example

```json
{
  "sub": "1234567890",
  "permissions": ["read:transaction"]
}
```

In this example, the caller can read invoices and payments.

To see the permissions required for each endpoint, check the [API documentation](https://api.numeraire.tech/docs).

### Wallet credits

Grant `credit:wallet` only to operators who may increase a wallet balance. A wallet owner
or editor needs this explicit permission to post a credit, including during setup.
For OAuth2/OIDC deployments, define the permission in the identity provider, grant it
to the operator and obtain a new access token. For existing local JWT accounts, an
administrator can add the permission through the account permission editor. When granting
access to an API key, include the scope in the key's own permission subset.
